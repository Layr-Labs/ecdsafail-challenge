Base: `bdfd306`, verified Q1024 route. Branch: `codex/midq-counter-tape`.
Worktree: `ecdsafail-midq-counter-tape`. Default OFF: `MIDQ_COUNTER_TAPE=1`.
Only `src/point_add` source changes. No trusted harness, simulator, dependency,
width, arithmetic guard, PZ step count (360), tail round count (224), or nonce
change. No submission or nonce search. This is an eligible isolated patch,
not a new Fiat-Shamir-clean submission and not an integration measurement of
the independent prefix/compiler/fast-route workers.

## Exactness and Early Termination

Detailed proof: `trailmix_port/inversion/counter_tape_proof.md`.
The flag is `[A=0 AND q=0]`, never `[A=0]` or just `[counter!=0]`.
Coprimality and `A*cb+B*(ca+q*cb)=p` imply B=1, ca=p on this branch.
The controlled map A->1, ca->p-cb yields two equal normalized coefficient
rows and the stationary (1,1) value orbit, with every logical tail sign zero.
All eight counter bits remain encoded in the first eight physical tape wires;
the decoder computes `!terminal AND encoded`. Reverse replay restores those
same physical QReg IDs, in the original bit order, before PZ uncomputation.
Terminal mapping is reversed and its flag cleaned before PZ replay too.

The production prefix's 360 coefficient widths are all <=248. Consequently
an exact-width PZ execution cannot reach ca=p there; done never increments its
counter, proving counter=0 without an empirical frequency assumption. True
early terminals are also handled exactly at a wider boundary, tested for ALL
256 counter encodings, including zero. This does NOT repair earlier truncation
or broken inactive-path promises. A separate emitted witness verifies that
255->0 reactivates the PZ body at q=0; wrap cannot silently be assumed safe.

## Validation

`MIDQ_COUNTER_TAPE_SELFTEST=1 target/release/build_circuit` passes using the
actual `crate::sim::Simulator` and the existing strict pre-reset checker:

- 43,520 exhaustive small map cases, including A=0,q>0 and modular wrap.
- 64 signed odd live pairs and all 256 terminal counter encodings through
  eight emitted rounds, signed overflow and original physical-ID restoration.
- 519 production-width stationary coefficient pairs, three forced/random
  measurement streams, forward and inverse values/phases/pre-reset scratch.
- Complete tail: 192 baseline + 960 sharing cases per checkpoint setting,
  both checkpoint OFF and ON; all 224 rounds, quotient codec, CTZ normalization,
  endpoint, reverse replay, phases, and every reset checked before execution.
- Configured 360/224/eight-bit constants and every prefix coefficient width.

The final post-format release build and full selftest also pass with
`LOWQ_COMPACT_KGANC=1` and both vent caps explicitly set to 1019.

Independent fixed 9024 corpus: exactly the inherited classical failures
4174, 4968, 5407, 7617, 7854. Phase failures only at 5407 and 7854, both in
that set. Zero ancilla failures and no new any-channel failing inputs. The
diagnostic correctly exits FAIL; this corpus is not advertised as clean.
Its candidate average T is 17,226,092.182 (different from the frozen corpus).

An initial synthetic tiny-coefficient test, codec OFF, returned p+1 instead
of canonical 1 for A=7,B=5,ca=7,cb=p-5,parity=0. Its cross sum is 7p, not p;
it is outside adjacent-PZ integer support. Passing live tests use nondegenerate
full-width modular rows. This does not exclude any new production input or
weaken the separately exhaustive terminal-counter coverage.

`cargo build --offline --release --bin build_circuit` passes. The known broken
baseline library tests were not used. Count-only profiling also has an existing
empty-op-vector slice panic in `midq_toffoli_since`; actual emitted builds were
used instead, without modifying the other worker's profiling code.
